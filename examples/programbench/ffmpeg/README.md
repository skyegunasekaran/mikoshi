# ProgramBench FFmpeg cleanroom

This environment prepares the public
[ProgramBench FFmpeg task](https://github.com/facebookresearch/ProgramBench/tree/895f65916bc5ba34a915d36da321fde0301125ad/src/programbench/data/tasks/ffmpeg__ffmpeg.360a402).
The task is to independently reimplement the reference program from its normal
CLI behavior and bundled documentation. It is not an FFmpeg source checkout.
None of the helpers starts inference or a paid experiment.

Generated targets, run snapshots, deployment files, and validation receipts
stay local and are excluded from Git. The reusable setup, grading helpers, and
pinned recipes are tracked here.

## Spending

Mikoshi stops gracefully at the configured `budget_usd`, but in-flight requests
settle afterward and can push spending slightly past it. If you need a hard
ceiling, set `budget_usd` a little below it (for example 2.5% lower) or watch
`mikoshi status` and run `mikoshi stop` yourself.

## Pinned inputs

- ProgramBench 1.2.5, commit `895f65916bc5ba34a915d36da321fde0301125ad`, including its frozen `uv.lock`.
- Instance `ffmpeg__ffmpeg.360a402`.
- Official `task_cleanroom_v6` image for inference and the base of candidate grading.
- Official `task_v6` image used only to construct a private reference control.
- [Test fixtures](https://huggingface.co/datasets/programbench/ProgramBench-Tests/tree/5954a1957b5e0d770ec2c5523506abd212806315/ffmpeg__ffmpeg.360a402) pinned to `5954a1957b5e0d770ec2c5523506abd212806315`.
- Image digests, task metadata, and resource settings in [environment.lock.json](environment.lock.json).

The task metadata names source commit `360a4025fb2582d52d871ea2129d6b659598bb49`,
while the distributed binary reports `git-2026-06-11-7da4887c`. We preserve the
official binary and record that distinction rather than rebuilding a different
version. Its build disables ffplay, ffprobe, and autodetection and enables zlib,
lzma, and iconv.

The public manifest lists 4,165 tests, of which 1,124 are ignored by ProgramBench;
3,041 contribute to the score. All 12 active branches run, including the two
documented empty suites for subcommands and TUI behavior. Grading applies the
upstream active-branch, expected-test, and ignored-test filters without editing
the manifest or tests.

## Setup and fresh targets

From the Mikoshi repository root, with its Python 3.12+ environment, uv, Git,
and Docker available:

```sh
.venv/bin/python examples/programbench/ffmpeg/environment.py setup
.venv/bin/python examples/programbench/ffmpeg/environment.py prepare tmp/programbench/ffmpeg/targets/trial-001
.venv/bin/python examples/programbench/ffmpeg/environment.py smoke --target tmp/programbench/ffmpeg/targets/trial-001
```

`setup` fetches the exact benchmark revision, installs its frozen dependencies
into a separate host environment, caches all FFmpeg test archives, and records
SHA-256 checksums and immutable image IDs. Matching inputs are reused;
`setup --rebuild` rebuilds the three local image adaptations. A corrupt fixture is
an error, not a reason to silently download different data.

`prepare` refuses an existing target. It copies only the cleanroom's README,
license files, and two sample media assets, then creates a fresh Git history
with a `baseline` tag. Provenance is saved beside the target. Create a fresh
target for every trial or comparison arm.

The reference lives at `/opt/programbench-reference/executable` in every command
container. It is owned by root with execute-only permissions. It is deliberately
outside the mounted target, so the agent's new `./executable` cannot overwrite
it and host file tools cannot read or copy it. Moving the reference is the local
adaptation to Mikoshi's separate command containers; the instructions use its
actual path. The command image removes its bundled workspace and contains no
grader fixture, reference implementation source, or readable FFmpeg binary.

The smoke check uses the host UID/GID, `HOME=/tmp`, bridge networking, dropped
capabilities, and `no-new-privileges`, matching Mikoshi's command restrictions.
It compiles and executes C, C++, Rust, and Go programs; links zlib and lzma;
imports every pytest plugin; queries the reference; decodes the sample FLAC;
and checks an outbound HTTPS connection. It leaves the target clean.
`environment.py dependencies` additionally compares the complete installed
system/Python package inventories and toolchain versions between the actual
agent identity and root evaluator identity, saving `dependency-parity.json`.
The resulting package inventory stays local with the other validation receipts.

## Use with Mikoshi

Merge the `deployment` object from
`mikoshi-deployment.json`, generated by `setup`, into the experiment input.
It selects the recorded command image by immutable ID, `linux/amd64`, and
`network: bridge`. Use the contents of
[instruction-mikoshi.md](instruction-mikoshi.md) as the objective and set
`run.repository` to a newly prepared target. Keep run output outside the target.

Choose models, pricing, agent count, wall time, and spending limits separately
when designing the trials. Do not mount or expose this example directory,
`tmp/programbench/ffmpeg/benchmark`, test archives, grading output, or the control
image to agents. Test archives contain evaluator-only upstream material.
Provider credentials stay on the host.

All official images are `linux/amd64`. On Apple Silicon, Docker runs them under
emulation, so timings will be slower than on native hosts. Grading defaults to 4 CPUs,
8 GiB, 512 processes, and one branch container at a time, instead of the public
baseline's 20 CPUs and 60 GiB. `--cpus` and `--memory` can override grading
resources; these are recorded in each receipt. Agent networking is enabled
in this example. This is a local variation from ProgramBench's published
offline-inference protocol; the independent-implementation rules still apply.
Evaluation uses Docker's bridge network, as the upstream evaluator does: several
network error tests require a default route and working DNS to reproduce their
expected timeouts and NXDOMAIN responses. Using `network: none` for evaluation
made the reference fail 11 otherwise scored tests. No network tests are excluded
or rewritten. The upstream evaluator blackholes build-time DNS during compile;
evaluation pip calls use the pinned offline cache. Test execution restores DNS.
Agent pip calls may use the network. Vendor any downloaded source dependency
that is absent from the cleanroom so `compile.sh` can rebuild it offline.

## Export and grade a candidate

Freeze the target before exporting:

```sh
.venv/bin/python examples/programbench/ffmpeg/environment.py submit tmp/programbench/ffmpeg/targets/trial-001 tmp/programbench/ffmpeg/submissions/trial-001
.venv/bin/python examples/programbench/ffmpeg/environment.py grade tmp/programbench/ffmpeg/submissions/trial-001/ffmpeg__ffmpeg.360a402/submission.tar.gz --output tmp/programbench/ffmpeg/evaluations/trial-001
```

`submit` requires `compile.sh` and includes tracked and untracked, non-ignored
files, preserving modes and symlinks. Deleted files are omitted. Git metadata
and the generated root `executable` are excluded. Keep any required vendored
source in Git rather than ignoring it. Packaging preserves the real Git index
and refuses to overwrite an existing output directory.

The agent and evaluator images share hashed grading dependencies and an offline package
cache to the official cleanroom. The distributed image lacks `pytest-timeout`,
and the public test scripts otherwise try to install it online. All images use
[requirements.lock](requirements.lock). Evaluator and control images set
`PIP_NO_INDEX=1` and use their local cache to satisfy the original scripts'
pip calls offline; the agent image enables index access. The
agent command image inherits the evaluator's dependency layer, so an agent's
build and test tools are also available during fresh evaluation. No test or
scorer source is changed by this adaptation.

A public logging test calls `os.chdir(tmp_path)` without restoring it. That can
make later tests fail to find bundled relative media paths, depending on xdist
scheduling. [pytest_environment.py](pytest_environment.py) restores the previous
working directory after each test, in both agent and evaluator environments.
The repair is checked with the actual logging and media tests in that order.
No public test, expected result, or scoring exclusion is edited.

The unmodified pinned ProgramBench evaluator deletes the submitted executable,
builds via `compile.sh` in a fresh cleanroom, hashes the new executable, and tests
it in separate containers against every active public branch. It uses the
cached fixtures and an image alias derived from the verified immutable image ID.
Neither the agent's target nor host credentials are mounted in these containers.

Each evaluation contains `execution.json`, `console.log`, `summary.json`, and the
upstream `<instance_id>/<instance_id>.eval.json`. The receipt records fixture,
submission, helper, and recipe hashes; image ID; resources; and timestamps.
The summary exposes missing tests, branch errors, warnings, and status counts.
A nonzero helper exit needs investigation; inspect `console.log` and the full
upstream result before interpreting a score. The upstream info command can also
summarize an output:

```sh
tmp/programbench/ffmpeg/benchmark/.venv/bin/programbench info tmp/programbench/ffmpeg/evaluations/trial-001
```

If moving the repository invalidates a console script, rerun setup with a valid
Python interpreter to recreate the isolated environment.

## Controls and restoration

Repeat controls with fresh output directories:

```sh
.venv/bin/python examples/programbench/ffmpeg/environment.py control negative --branch 50e5453dfbd4 --output tmp/programbench/ffmpeg/checks/negative-repeat
.venv/bin/python examples/programbench/ffmpeg/environment.py control reference --output tmp/programbench/ffmpeg/checks/reference-repeat
.venv/bin/python examples/programbench/ffmpeg/environment.py archive
```

The negative control compiles a source program that always exits unsuccessfully.
The command above explicitly runs one behavioral branch (10 scored tests).
Its output is labeled `control_subset`; it is a diagnostic, not a full-instance
benchmark score. Omit `--branch` for a full negative control, which can take much
longer because upstream retries every deliberately failing test. This option is
available only on `control`; candidate `grade` always selects all active branches.
The private reference control copies the official gold binary from the full
image into the submission position, solely to validate the scorer. It is not a
valid agent submission or a reimplementation result. The full/control images
must never be used for inference or candidate grading.

`archive` saves all five image IDs to ignored `tmp/programbench/ffmpeg/images.tar`
and writes `images.tar.sha256`; an existing archive is never overwritten.
Keep the archive, `images.json`, `fixtures.json`, cached fixtures, benchmark
checkout and frozen lock, and these recipes together for restoration:

```sh
(cd tmp/programbench/ffmpeg && shasum -a 256 -c images.tar.sha256)
docker image load -i tmp/programbench/ffmpeg/images.tar
.venv/bin/python examples/programbench/ffmpeg/environment.py setup
```

Keep validation receipts in the ignored local state directory and record the
checks and control results actually obtained on your host.
